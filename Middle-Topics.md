## JavaScript — Основи

**Q: Що таке замикання (closure)?**

A: Замикання — це комбінація функції та лексичного середовища, в якому вона була визначена. Замикання надає внутрішній функції доступ до scope зовнішньої функції навіть після того, як зовнішня функція завершила виконання.

```js
function outer() {
  const x = 10;
  return function inner() {
    console.log(x); // має доступ до x через замикання
  };
}
const fn = outer();
fn(); // 10
```

---

**Q: Які є типи scope в JavaScript?**

A: Блочний, функціональний, вкладений, глобальний та лексичний.

---

**Q: Що таке `use strict` і що він забороняє?**

A: Директива, яка вмикає суворий режим. Забороняє:
- використання `with`
- `this` → `undefined` (замість глобального об'єкта)
- оголошення змінних без `var/let/const`
- зміну read-only властивостей
- дублювання ключів в об'єктних літералах
- вісімкові числа

---

**Q: Що таке `Promise` і які стани він має?**

A: `Promise` — об'єкт для відкладених та асинхронних обчислень. Три стани:
- **pending** — початковий, ще не виконаний і не відхилений
- **fulfilled** — операція завершена успішно
- **rejected** — операція завершена з помилкою

---

**Q: Що таке генератор (Generator function)?**

A: Функція, що може повертати (`yield`) кілька значень по одному, на вимогу. Позначається `function*`. Повертає iterator-об'єкт з методом `.next()`.

```js
function* gen() {
  yield 1;
  yield 2;
  yield 3;
}
const g = gen();
g.next().value; // 1
g.next().value; // 2

// Делегування через yield*
function* combined() {
  yield* genFirst();
  yield* genSecond();
}
console.log([...combined()]); // [1, 2, 3, 4, 5]
```

---

**Q: Що таке ітератор (Iterator)?**

A: Структура даних, яка вказує на елемент контейнера і вміє переходити до попереднього/наступного елемента. Будь-який об'єкт з методом `.next()`, що повертає `{ value, done }`.

---

**Q: Як зробити глибоку копію об'єкта?**

A: Кілька способів:
- `JSON.parse(JSON.stringify(obj))` — просто, але не копіює функції/undefined/циклічні посилання
- `structuredClone(obj)` — нативний API, підтримує більше типів
- Рекурсивна функція через `for...in`
- `_.cloneDeep(obj)` (lodash)

```js
function deepCopy(obj) {
  const copy = {};
  for (const key in obj) {
    copy[key] = typeof obj[key] === 'object' ? deepCopy(obj[key]) : obj[key];
  }
  return copy;
}
```

---

**Q: Чим відрізняється `for...in` від `for...of`?**

A: `for...in` ітерує по **ключах** об'єкта (включно з успадкованими). `for...of` ітерує по **значеннях** iterable-об'єктів (масив, рядок, Map, Set).

```js
for (const key in obj) {
  if (obj.hasOwnProperty(key)) { // виключити успадковані
    console.log(key, obj[key]);
  }
}
```

---

**Q: Як реалізувати асинхронний `filter`?**

A: `Array.prototype.filter` не підтримує async predicate. Рішення через `Promise.all`:

```js
async function asyncFilter(array, predicate) {
  const results = await Promise.all(
    array.map(async (el) => ({ el, ok: await predicate(el) }))
  );
  return results.filter(r => r.ok).map(r => r.el);
}
```

---

**Q: Що таке `Proxy` і `Reflect`?**

A: `Proxy` дозволяє перехоплювати та переозначати фундаментальні операції над об'єктом (читання, запис, виклик). `Reflect` — вбудований об'єкт, що надає методи, аналогічні handler-методам Proxy, для виконання стандартних JS-операцій.

```js
const p = new Proxy(target, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver);
  }
});
```

---

**Q: Що таке `Object.create()`?**

A: Створює новий об'єкт із вказаним прототипом і властивостями. Дозволяє явно задати прототипний ланцюг.

---

**Q: Що таке клас в JavaScript?**

A: Синтаксичний цукор над прототипним наслідуванням, введений в ES2015. Ключове слово `super` у `constructor` викликає конструктор батьківського класу. Самі по собі не вводять нову ООП-модель.

---

**Q: Що таке callback-функція?**

A: Функція, що передається як аргумент і викликається у відповідь на певну подію або після завершення іншої операції.

---

## JavaScript — Асинхронність та Event Loop

**Q: Як працює Event Loop в JavaScript?**

A: JS є однопоточним. Event Loop координує:
- **Call Stack** — стек виконання синхронного коду
- **Web API** — браузерне середовище для async-операцій (setTimeout, fetch, etc.)
- **Microtask queue** — черга мікрозадач (вищий пріоритет)
- **Macrotask queue** — черга макрозадач (нижчий пріоритет)

Після кожної макрозадачі Event Loop повністю очищує чергу мікрозадач перед тим, як взяти наступну макрозадачу.

---

**Q: Що створює мікрозадачі (microtasks)?**

A:
- Promises (`.then`, `.catch`, `.finally`)
- `queueMicrotask()`
- `MutationObserver`

---

**Q: Що створює макрозадачі (macrotasks)?**

A:
- Таймери: `setTimeout`, `setInterval`
- Events: кліки, завантаження зображень тощо
- Браузерні нюанси: рендер, I/O

---

**Q: Який порядок виконання: `setTimeout(fn, 0)` чи `Promise.resolve().then(fn)`?**

A: Спочатку виконається `Promise.resolve().then(fn)`, бо Promises потрапляють до черги мікрозадач, яка має вищий пріоритет над чергою макрозадач (куди йде `setTimeout`).

## JavaScript — Патерни проектування

**Q: Які є категорії патернів проектування?**

A: Три категорії:
- **Creational (Породжуючі)** — відповідають за створення об'єктів
- **Structural (Структурні)** — описують, як організувати об'єкти та класи
- **Behavioral (Поведінкові)** — описують взаємодію між об'єктами

---

**Q: Які є Creational-патерни? Поясни кожен.**

A:
- **Constructor** — використовується для створення об'єктів (до появи class-компонентів в JS)
- **Factory** — визначає загальний інтерфейс для створення об'єктів в суперкласі, дозволяючи підкласам змінювати тип об'єктів
- **Prototype** — дозволяє копіювати об'єкти, не вдаючись у деталі їх реалізації
- **Singleton** — гарантує існування лише одного екземпляра класу без можливості перезапису

---

**Q: Які є Structural-патерни? Поясни кожен.**

A:
- **Adapter** — дозволяє несумісним інтерфейсам працювати разом; використовується при рефакторингу або об'єднанні нового та старого функціоналу
- **Decorator** — додає шар метаданих до інстансу і повертає його; дозволяє динамічно додавати нову функціональність
- **Flyweight** — економить пам'ять, розділяючи спільний стан між об'єктами замість дублювання
- **Facade** — надає простий інтерфейс до складної системи класів
- **Proxy** — підставляє замість реального об'єкта об'єкт-замінник, який перехоплює виклики до оригіналу

---

**Q: Які є Behavioral-патерни? Поясни кожен.**

A:
- **Chain of Responsibility** — передає запити по ланцюжку обробників
- **Command** — перетворює запити на об'єкти; підтримує чергу, логування та скасування операцій
- **Iterator** — послідовний обхід елементів без розкриття внутрішньої структури
- **Mediator** — зменшує зв'язність класів, переміщуючи зв'язки в один клас-посередник
- **Observer** — механізм підписки: об'єкти стежать і реагують на події інших об'єктів
- **State** — об'єкт змінює поведінку залежно від свого внутрішнього стану
- **Strategy** — визначає сімейство алгоритмів і дозволяє їх взаємозамінювати під час виконання
- **Template Method** — визначає скелет алгоритму, делегуючи деякі кроки підкласам

## Структури даних та алгоритми (Big O)

**Q: Що означає нотація Big O?**

A: Big O описує асимптотичну складність алгоритму — як зростає час виконання або використання пам'яті зі збільшенням вхідних даних.

---

**Q: Перерахуй основні класи складності від кращого до гіршого.**

A:
| Нотація | Назва | Приклад |
|---|---|---|
| O(1) | Константна | Доступ до елемента масиву за індексом |
| O(log n) | Логарифмічна | Бінарний пошук |
| O(n) | Лінійна | Перегляд усіх елементів масиву |
| O(n log n) | Лінійно-логарифмічна | Merge sort, Heap sort |
| O(n²) | Квадратична | Bubble sort, Insertion sort |
| O(n³) | Кубічна | Три вкладених цикли |
| O(n!) | Факторіальна | Перебір всіх комбінацій |

---

**Q: Порівняй алгоритми сортування за складністю.**

A:
| Алгоритм | Best | Average | Worst | Space |
|---|---|---|---|---|
| Quicksort | Ω(n log n) | Θ(n log n) | O(n²) | O(log n) |
| Mergesort | Ω(n log n) | Θ(n log n) | O(n log n) | O(n) |
| Timsort | Ω(n) | Θ(n log n) | O(n log n) | O(n) |
| Heapsort | Ω(n log n) | Θ(n log n) | O(n log n) | O(1) |
| Bubble Sort | Ω(n) | Θ(n²) | O(n²) | O(1) |
| Insertion Sort | Ω(n) | Θ(n²) | O(n²) | O(1) |
| Selection Sort | Ω(n²) | Θ(n²) | O(n²) | O(1) |
| Radix Sort | Ω(nk) | Θ(nk) | O(nk) | O(n+k) |
| Counting Sort | Ω(n+k) | Θ(n+k) | O(n+k) | O(k) |

## DOM

**Q: Що таке DOM?**

A: Document Object Model — деревоподібне представлення HTML-документа у вигляді об'єктів. Браузер будує DOM з HTML, і саме через DOM JavaScript взаємодіє зі сторінкою. Ієрархія: `window → document → html → head/body → ...`

---

**Q: Що таке Virtual DOM і навіщо він потрібен?**

A: Virtual DOM — легковагова копія реального DOM у пам'яті (JS-об'єкт). React зберігає Virtual DOM, і при зміні стану порівнює (diff) нове дерево зі старим, а потім оновлює лише змінені вузли реального DOM. Це ефективно, бо DOM-операції — найдорожчі в JS.

---

**Q: Що таке Reconciliation в React?**

A: Процес порівняння нового Virtual DOM зі старим (diffing) та визначення мінімального набору змін для оновлення реального DOM. Реалізований через механізм **Fibers** — JS-об'єктів, що представляють одиниці роботи.

---

## React — Основи

**Q: Які типи компонентів є в React?**

A:
- **Class components** — ES6-класи, мають доступ до lifecycle-методів
- **Function components** — прості JS-функції, використовують хуки замість lifecycle-методів
- **Pure components** — class-компоненти з `shouldComponentUpdate` на основі shallow comparison
- **HOC (Higher Order Components)** — функції, що приймають компонент і повертають новий компонент з розширеною поведінкою

---

**Q: Що таке HOC (Higher Order Component)?**

A: Функція, що приймає компонент і повертає новий компонент з додатковими пропсами або поведінкою. `memo` — HOC, `useMemo` — хук.

```js
const MyMemoComponent = memo(MyCustomComponent, (prevProps, nextProps) => {
  // повернути true, якщо ре-рендер не потрібен
});
```

---

**Q: Що таке Error Boundary?**

A: Компонент (тільки class-компонент), який перехоплює помилки в дочірньому дереві і відображає fallback UI замість краша. Реалізується через `componentDidCatch` та `getDerivedStateFromError`.

---

**Q: Що таке SyntheticEvent в React?**

A: Кросбраузерна обгортка над нативною подією браузера. Має той самий інтерфейс (включно з `stopPropagation()`, `preventDefault()`), але гарантує однакову поведінку в усіх браузерах. Нативну подію можна отримати через `event.nativeEvent`.

---

**Q: Що таке `forceUpdate()`?**

A: Метод class-компонента, який примусово запускає ре-рендер, пропускаючи `shouldComponentUpdate()`. Не рекомендується — краще управляти станом через `setState`.

---

**Q: Що таке Refs і навіщо вони?**

A: Refs (references) дозволяють отримати прямий доступ до DOM-елемента або React-компонента. Швидше за querySelector. Створюються через `React.createRef()` або хук `useRef`. Значення ref не викликає ре-рендер при зміні.

---

## React — Lifecycle

**Q: Які фази lifecycle має React-компонент?**

A: Три фази: **Mounting**, **Updating**, **Unmounting**.

---

**Q: Які методи викликаються під час Mounting?**

A: (у порядку виклику)
1. `constructor`
2. `getDerivedStateFromProps`
3. `render` *(Render phase — чиста, без side effects)*
4. React оновлює DOM та refs *(Commit phase)*
5. `componentDidMount`

---

**Q: Які методи викликаються під час Updating?**

A: (у порядку виклику — тригери: нові пропси, `setState()`, `forceUpdate()`)
1. `getDerivedStateFromProps`
2. `shouldComponentUpdate` *(може зупинити процес)*
3. `render`
4. `getSnapshotBeforeUpdate` *(Pre-commit phase — може читати DOM)*
5. React оновлює DOM та refs
6. `componentDidUpdate`

---

**Q: Який метод викликається під час Unmounting?**

A: `componentWillUnmount` — використовується для cleanup (скасування підписок, таймерів тощо).

---

**Q: Що таке `shouldComponentUpdate`?**

A: Lifecycle-метод, що дозволяє контролювати, чи потрібен ре-рендер при зміні пропсів або стану. Повертає `true` (ре-рендер) або `false` (пропустити). Інструмент оптимізації продуктивності.

---

**Q: Що таке `getSnapshotBeforeUpdate`?**

A: Викликається безпосередньо перед тим, як зміни буде застосовано до DOM. Дозволяє зчитати інформацію з DOM (наприклад, позицію скролу) до оновлення. Результат передається як третій аргумент у `componentDidUpdate`.

---

**Q: Що таке `getDerivedStateFromError`?**

A: Статичний lifecycle-метод, що викликається, коли дочірній компонент кидає помилку під час рендерингу. Дозволяє оновити стан, щоб відобразити fallback UI. Приймає помилку та повертає об'єкт стану.

---

## React — Hooks

**Q: Що таке `useRef`?**

A: Хук для отримання посилання на DOM-елемент або збереження значення між рендерами. Значення `useRef` **не викликає ре-рендер** при зміні. Підходить для значень, які змінюються, але не повинні тригерити оновлення UI.

---

**Q: Що таке `useReducer`?**

A: Хук для управління складним станом у функціональних компонентах. Альтернатива `useState` для складної логіки стану.

```js
const [state, dispatch] = useReducer(reducerFn, initialState);
// reducerFn(currentState, action) => newState
```

Переваги: зручне тестування, централізована логіка змін стану, уникнення зайвих ре-рендерів.

---

**Q: Чим відрізняється `useMemo` від `memo`?**

A: `memo` — HOC, огортає компонент і запобігає ре-рендеру, якщо пропси не змінились. `useMemo` — хук, мемоізує **обчислене значення** всередині компонента.

---

## Redux

**Q: Що таке Redux і які його основні елементи?**

A: Redux — бібліотека для управління глобальним станом. Основні елементи:
- **Actions** — JSON-об'єкти з описом змін стану (`{ type, payload }`)
- **Store** — єдиний об'єкт, де живе весь стан застосунку
- **Reducers** — чисті функції `(state, action) => newState`

---

**Q: Який data flow в Redux?**

A: UI → **Action Creator** → **Dispatcher** → **Root Reducer** → **Store** → **State** → UI

---

**Q: Що таке Middleware в Redux?**

A: Прошарок між Action та Reducer. Перехоплює dispatched actions і може виконувати side effects (API-запити, логування тощо) перед тим, як action дійде до reducer. Приклади: `redux-thunk`, `redux-saga`.

---

**Q: Що таке Reducers?**

A: Чисті функції, що приймають поточний стан та об'єкт Action і повертають новий стан. Не мають side effects, не мутують стан — повертають новий об'єкт.

---

**Q: Як підписатись на зміни Store?**

A: `store.subscribe(listener)` — викликає `listener` кожного разу, коли Store оновлюється.

---

## REST API

**Q: Що таке statelessness у REST?**

A: Кожен HTTP-запит повинен містити всю необхідну інформацію для обробки. Сервер не зберігає стан клієнта між запитами. Переваги: масштабованість, надійність, простота кешування.

---

**Q: Який HTTP-метод використовується для створення нового ресурсу?**

A: `POST`. Запит надсилається на endpoint ресурсу з тілом (зазвичай JSON). Успішна відповідь — `201 Created`.

---

**Q: Які HTTP-методи є ідемпотентними?**

A: `GET`, `HEAD`, `PUT`, `DELETE` — ідемпотентні (повторний виклик з тими самими даними дає той самий результат). `POST` — **не ідемпотентний**: кожен виклик створює новий ресурс.

---

**Q: Який HTTP-код повертається, якщо користувач намагається отримати доступ до чужого ресурсу?**

A: `403 Forbidden` — сервер розуміє запит, але відмовляє в авторизації (автентифікований, але немає прав).

---

**Q: Що таке HATEOAS?**

A: Hypermedia as the Engine of Application State — constraint REST, при якому сервер вбудовує гіперпосилання у відповіді, дозволяючи клієнту динамічно навігувати API без попереднього знання його структури.

```json
{
  "id": 123,
  "links": {
    "self": { "href": "/api/resources/123" },
    "children": { "href": "/api/resources/123/children" }
  }
}
```

---

**Q: Як додати заголовок `Cache-Control` до відповіді?**

A: Встановити у відповіді сервера:
```
Cache-Control: max-age=3600
```
Для заборони кешування:
```
Cache-Control: no-cache, no-store
```

---

**Q: Що таке внутрішній API-трафік організації?**

A: Комунікація між різними частинами внутрішніх систем організації через API. Захищається внутрішніми механізмами автентифікації (service accounts, RBAC, IAM).

---

**Q: Який REST constraint дозволяє наявність кешування, роутингу та проміжних систем між клієнтом і сервером?**

A: **Layered System** — constraint, що дозволяє наявність проміжних рівнів (кеші, балансувальники навантаження, шлюзи, проксі). Клієнт не знає, з яким рівнем він взаємодіє безпосередньо.

---

**Q: Що таке Code on Demand?**

A: Опціональний REST constraint, при якому сервер надає виконуваний код клієнту (наприклад, JavaScript у веб-застосунку або клієнтські бібліотеки API).

---

**Q: Який стандартний підхід до версіонування API?**

A: Включення номера версії в URL endpoint:
```
https://api.example.com/v1/resources
https://api.example.com/v2/resources
```

---

**Q: Який scope запитувати в OAuth для операцій запису?**

A: Залежить від API. Зазвичай scope містить слово `write` або назву ресурсу з правами запису. Наприклад, у GitHub API: `repo` для читання/запису репозиторіїв. Запитувати лише необхідні scopes — не більше.

## SDLC / Scrum

**Q: Що таке SDLC?**

A: Software Development Life Cycle — цикл розробки програмного забезпечення.

---

**Q: Які три основні принципи (кити) Scrum?**

A:
- **Прозорість** — кожен знає, що робить інший член команди
- **Інспекція** — перевірка та ревью процесів і виконаної роботи, відстеження артефактів та відхилень
- **Адаптація** — внесення змін у разі необхідності

---

**Q: Що таке Scrum 3-5-3?**

A:
- **3 Roles**: Product Owner, Development Team, Scrum Master
- **5 Events**: Sprint (1 тиждень – 1 місяць), Sprint Planning, Daily Meeting, Grooming (оцінка складності в story points), Sprint Review, Retrospective
- **3 Artifacts**: Product Backlog, Sprint Backlog, Product Increment (ready for development → done)

---

**Q: Що таке Story Points?**

A: Абстрактні одиниці оцінки складності завдань у Scrum. Відображають не час, а відносні зусилля, необхідні для виконання задачі. Виставляються під час Grooming.
